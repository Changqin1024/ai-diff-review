# AI Diff Review

对 AI 编码智能体（opencode、Cursor、Claude Code、Trae、Aider 等）产生的文件改动进行 **逐块人工审查**：可以逐条接受、逐条拒绝，也可以按文件或一键全部接受 / 拒绝。

## 原理

扩展在文件系统层面记录一份 **基线（baseline）**，即改动之前的文件内容。之后任何外部程序（包括 opencode）对工作区文件的改动都会被文件监听器捕获，并与基线对比生成 diff：

- **接受**：把基线推进到当前磁盘内容 —— 保留这次改动，不再显示为待审查。
- **拒绝**：把磁盘内容回退到基线 —— 丢弃这次改动。

因为接受 / 拒绝只影响被选中的 diff 块，所以可以做到“改 10 处，接受 7 处、拒绝 3 处”。

## 使用

1. 用 VS Code 打开工程目录。
2. 左侧活动栏出现 **AI 审查** 图标，状态栏显示 `AI 审查: N`。
3. 让 AI 智能体改文件，改动会被实时捕获。
4. 在侧边栏或审查面板里逐块 / 按文件 / 全局接受或拒绝。

## 审查入口

**侧边栏（AI 审查 活动栏）**
- **待审查改动**：树视图，按 **文件夹层级嵌套**（文件夹 → 文件 → 改动块）。点击文件在审查面板中打开；点击改动块会**跳转定位**到对应位置；行内按钮可逐块 / 按文件接受或拒绝。右键文件节点可 **打开文件 / 在资源管理器中显示 / 打开原生对比**。
- **全局操作**：**全部接受 (N) / 全部拒绝 (N)**，作用于所有待审查文件。
- **设置**：点顶部齿轮进入的**整页设置**（进入后整个侧边栏都是设置页，`← 返回` 退出），详见下文。

**审查面板（Webview，推荐）**
- 每次只显示**当前打开的那一个文件**，显示**整份文件内容**（未改动行也完整显示，改动行高亮，删除行就地插入）；或在设置里改为**仅变更片段**。
- 顶部是当前文件操作：**接受当前文件 / 拒绝当前文件**（外加刷新）。
- 文件信息条：路径 / 状态 / 增删统计 + **打开原生对比 / 在资源管理器中显示**。
- 每个改动块头部有块级 **接受 / 拒绝**，不遮挡代码。
- 任何操作后剩余块、行号、增删计数**实时刷新**。
- 当前文件**不会自动跳到下一个**：没有差异后继续显示该文件**操作后的最终内容**（全接受=接受后内容，全拒绝=原始内容，部分=最终结果）。要换文件在左侧点击。

**原生 diff 编辑器**
- 点 `打开原生对比` 打开 VS Code 内置 diff（基线 ↔ 工作区，整份文件）。
- 块级操作在**悬停菜单**里（鼠标移到某块出现 `接受此改动 / 拒绝此改动`）；标题栏只有文件级按钮。
- 接受 / 拒绝后两侧实时更新；文件全部审查完毕后其 diff 标签页**自动关闭**。

## 侧边栏「设置」页

- **启动监听**：默认开。关闭=停止监听并清空列表；打开=按当前范围重建基线。
- **监听路径**：只追踪所选文件/文件夹（工作区内，可多选）；留空=整个工作区。**动态生效**：路径不存在则不生效；若配置的路径全部失效则自动回退为整个工作区。
- **排除（本工作区）**：加入排除路径/glob 时，会**自动删除其已存基线**；与全局 `aiReview.ignore` 相互独立、同时生效。
- **缓存**：显示当前目录与占用；**选择目录… / 恢复默认**；更改后把已有基线**移动**到新目录（不复制）；**清理**删除当前工作区全部基线。
- **内容**：
  - **追踪二进制文件**（默认关）：关闭时会**延迟 5 秒**删除已存的二进制基线（期间重开则取消）。
  - **diff 显示范围**：整份文件（默认）/ 仅变更片段。
  - **复用 VS Code 编码识别**（默认关）：仅当 VS Code 的 `files.autoGuessEncoding` 已开启时可启用；开启后按 VS Code 的自动猜测解码/回写，关闭则用内置检测。
- **基线**：**重置基线**（以当前内容重新开始，丢弃所有待审查项）。

## 编码支持

- 自动识别文件编码（UTF-8、GBK/GB2312、GB18030、Big5、Shift_JIS、EUC 等），中文注释不再乱码；**拒绝回写时保持原编码**。
- 或在设置里「复用 VS Code 编码识别」，直接把编码判定交给 VS Code 的 `files.autoGuessEncoding`。

## 重命名 / 移动

改动文件被重命名或移动时，会尽量**搬迁基线**（而不是删除再重建）：
- 有 git 时用重命名检测（含相似度，改名同时改内容也能识别）；
- 否则用内容哈希匹配（纯改名 / 移动）。

## 命令（命令面板 `Ctrl+Shift+P`）

| 命令 | 说明 |
| --- | --- |
| `AI 审查: 打开审查面板` | 打开完整审查面板 |
| `AI 审查: 记录基线` | 为还没有基线的文件补记基线（幂等，不破坏已有待审查项） |
| `AI 审查: 设置` | 进入侧边栏整页设置 |
| `AI 审查: 刷新` | 重新扫描工作区 |
| `AI 审查: 全部接受` | 接受全部改动 |
| `AI 审查: 全部拒绝` | 拒绝全部改动（有确认弹窗） |
| `AI 审查: 打开原生对比` | 打开 VS Code 内置 diff |
| `AI 审查: 打开文件` | 打开工作区真实文件（右键菜单） |
| `AI 审查: 在资源管理器中显示` | 在资源管理器中定位文件 |
| `AI 审查: 清理当前工作区缓存` | 删除当前工作区全部基线 |
| `AI 审查: 重置基线` | 清空基线并以当前内容重新开始（侧边栏设置页也有） |

> `接受/拒绝当前文件`、`接受/拒绝此改动`、`打开文件` 等为树视图 / 面板 / 右键菜单的内联操作，不在命令面板中显示。

## 设置项

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| `aiReview.autoCheckpoint` | `true` | 激活时自动记录基线（仅补齐缺失的基线） |
| `aiReview.baselineFromGit` | `false` | 以 git `HEAD` 作为基线，让已有的未提交改动也进入审查 |
| `aiReview.ignore` | 见下 | 不纳入审查的 glob（全局） |
| `aiReview.maxTextFileKB` | `4096` | 超过此大小的文本文件只支持文件级接受 / 拒绝 |
| `aiReview.showStatusBar` | `true` | 显示状态栏计数 |
| `aiReview.debounceMs` | `150` | 文件变更防抖时间（毫秒） |
| `aiReview.watch.enabled` | `true` | 是否自动监听（工作区级） |
| `aiReview.watch.paths` | `[]` | 仅监听的文件 / 文件夹（工作区级，留空=整个工作区） |
| `aiReview.watch.exclude` | `[]` | 本工作区额外排除的路径 / glob（工作区级） |
| `aiReview.cacheDir` | `""` | 基线缓存目录（工作区级，留空=扩展默认存储；更改会迁移基线） |
| `aiReview.trackBinaryFiles` | `false` | 是否追踪二进制文件（工作区级） |
| `aiReview.diffDisplay` | `"full"` | diff 显示范围：`full` 整份 / `hunks` 仅变更片段（工作区级） |
| `aiReview.reuseVSCodeEncoding` | `false` | 复用 VS Code 编码识别（工作区级，需 `files.autoGuessEncoding` 开启） |

默认忽略：`.git`、`node_modules`、`.vscode-test`、`out`、`dist`、`build`、各类 lock 文件、`*.vsix` 等。

## 与 opencode 配合

opencode 直接写入磁盘文件，扩展监听器会自动捕获，无需额外集成。推荐：

1. 让扩展激活（打开过一次工作区即可）。
2. AI 改完文件后在「AI 审查」里审查。
3. 逐块接受 / 拒绝，或一键处理。

若希望审查范围是相对 `HEAD` 的所有改动，可设 `aiReview.baselineFromGit: true`。

## 已知限制

- 只追踪工作区内的文件（`file` scheme）。
- 二进制文件默认不追踪（可在设置开启）；超大文件仅支持文件级接受 / 拒绝。
- 编码识别为启发式；极短或歧义的文本可能识别不准（会回退 UTF-8）。可开启「复用 VS Code 编码识别」。
- 基线默认存在扩展的 workspace storage，可在设置里改到自定义目录；不污染工程目录，但不同机器 / 工作区之间不共享。
- 未保存的编辑器缓冲不参与比较，比较对象是磁盘内容。
- 无 git 且“改名同时改内容”时，重命名可能退化为删除+新增。
